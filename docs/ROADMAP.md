# SweetToon 과제 로드맵

이 문서는 2026년 8월 2일 제출을 위한 기능 우선순위와 완료 경계를 관리한다.
아키텍처 결정의 정본은 Katsuranbo-Wiki에 두고, 이 문서에는 현재 구현 순서와
사용자 관점의 완료 조건만 기록한다.

## 완료된 기반

- 독자: 작품 탐색 → 작품·회차 선택 → 세로 스크롤 감상
- 홈·작품·뷰어의 서버 렌더링, 페이지별 메타데이터와 구조화 데이터
- Express API, PostgreSQL migration과 멱등 시드
- 실제 인쇄 API를 호출하지 않는 `MockPrintProvider` 경계
- 완결 시즌의 Mock 견적 → 영속 주문 → 제작 타임라인
- ZIP/CBZ 원고의 보안 검증 → 자연 정렬 미리보기 → 에피소드 등록
- 로컬 검증과 Jenkins가 공유하는 웹·서버·Compose 하네스
- 검증된 `dev` SHA만 `.48` 개발 환경에 배포하는 CI/CD
- 28개 작품의 상태·요일·장르 탐색과 페이지 단위 이어 불러오기
- 5화 단위 권, 작품별 무료 정책, Mock 주문 기반 브라우저 해금
- 세로/양면 리더, 익명 책갈피·진행도, 한국 시간 주문 타임라인
- Swagger/OpenAPI와 filesystem/R2 교체형 작품 스토리지

## 구현 우선순위

### P0. 독자 소장본 주문 (완료)

완결 시즌 선택 → 판형·표지·수량 선택 → 견적 확인 → 주문 생성 → 주문 상태
타임라인까지 한 흐름으로 연결한다.

완료 조건:

- PostgreSQL `Order`와 `OrderEvent`가 주문의 로컬 진실 공급원이다.
- 견적·접수·인쇄사 상태는 `PrintProvider`를 통해서만 접근한다.
- 새로고침과 서버 재기동 후에도 주문과 상태 이력이 유지된다.
- 로딩, 검증 오류, 주문 실패, 완료 상태가 사용자 언어로 구분된다.
- 실제 결제, 배송사, `api.sweetbook.com` 요청은 발생하지 않는다.

### P1. 창작자 스튜디오 ZIP/CBZ 업로드 (완료)

작가가 이미지 묶음을 한 번에 올리고, 자연 정렬된 페이지 순서를 확인한 뒤
에피소드로 등록할 수 있게 한다.

완료 조건:

- zip-slip, 파일 수·크기·압축 해제 총용량 제한을 검증한다.
- PNG, JPEG, WebP만 허용하고 SVG와 실행 가능한 콘텐츠를 거부한다.
- MIME signature와 확장자를 교차 확인한다.
- `1, 2, 10` 순서의 natural sort와 등록 전 미리보기를 제공한다.
- 실패 시 고아 파일이나 불완전한 DB 행을 남기지 않는다.

### P2. 운영자 주문 관리 (완료)

운영자가 주문 목록을 필터링하고 허용된 상태 전이만 수행하며, 변경 이력을
확인할 수 있게 한다.

완료 조건:

- 상태 전이 규칙을 service 계층에서 검증한다.
- 모든 변경은 `OrderEvent`로 남는다.
- 빈 목록, 잘못된 전이, 동시 갱신 실패가 구분된다.
- CSV 내보내기는 핵심 상태 관리가 끝난 뒤의 가점 범위다.

### P3. 제출 완성도

- 클린 클론에서 `docker compose up --build`를 검증한다.
- 모바일·키보드·대표 오류 흐름을 실제 브라우저에서 확인한다.
- README에 사용자, 구현 범위, Mock 정책, 실행법과 설계 근거를 맞춘다.
- 더미 콘텐츠의 시각 품질을 보강하되 핵심 기능 검증보다 우선하지 않는다.
- 기본 filesystem Compose와 선택형 MinIO 스토리지 경계를 각각 스모크 검증한다.

## 비대상 범위

- 회원 가입·로그인과 역할 권한 시스템
- 실제 결제, 배송 추적, 이메일·푸시 알림
- 실제 Book Print API 또는 다른 외부 인쇄 서비스 호출
- Komga 서버 연동
- 모바일 앱과 추천·소셜 기능
- CBZ 디지털 다운로드는 시간이 남을 때만 검토하는 선택 범위
